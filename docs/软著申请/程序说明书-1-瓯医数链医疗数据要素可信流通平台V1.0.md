## 第 1 页：软件概述

### 1.1 开发目的
医疗数据因安全合规约束难以跨机构流通，导致 AI 模型训练数据不足、数据资产无法变现。本软件开发目的：
1. 为医疗机构提供"原始数据不出院、数据价值可流通"的数据要素交易基础设施；
2. 建立数据产品目录、授权交易、收益分成、审计存证的完整闭环；
3. 为监管方提供实时监管看板，满足《数据安全法》《个人信息保护法》合规要求；
4. 承载多智能体医疗应用生态（9 个智能体），形成数据消费侧的规模化需求。

### 1.2 主要功能
数据产品目录管理、数据要素授权交易与收益分成（医院70%/平台20%/数据贡献者10%）、
审计存证链（sha256 哈希串联，防篡改）、监管合规看板（卫健/数据局视角）、
用户注册登录与 JWT 鉴权、管理员超级面板、可信数据空间演示、
多智能体医疗应用生态（医保政策问答、报销引擎、药物相互作用扫描、健康画像、
3D 人体档案、泛癌筛查、影像分析、EEG 脑电分析、数据管家）。

### 1.3 运行环境
- 硬件：4 核 CPU / 8GB 内存起（本地大模型推理建议 16GB）
- 操作系统：Windows 10+ / Ubuntu 22.04+ / 信创环境适配
- 支撑软件：Python 3.11+、Node.js 20+、PostgreSQL 16（或 SQLite）、Ollama（可选）
- 开发语言：Python（FastAPI 后端）、TypeScript（React 18 / Next.js 14 前端）
- 部署形态：Docker 一键部署；已在魔搭创空间公网部署并 5 分钟保活

## 第 2 页：系统结构（一）总体架构

平台采用前后端分离架构，三层结构：

    前端（Next.js 14 / React 18 / TypeScript）
      ├─ 数据要素市场页   产品目录/交易记录/监管看板
      ├─ 联邦协作网络页   任务发起/收敛曲线/逐院公平性/存证链
      ├─ AI病历治理页     病历输入/脱敏对比/结构化结果
      ├─ 可信数据空间页   可用不可见演示/真实事件流
      ├─ 安全中心页       敏感事件/审计链校验
      └─ 多智能体应用页   医保问答/报销/药物扫描/健康画像等 9 个应用
    后端（FastAPI / Python 3.11，20 个路由模块）
      ├─ routers/marketplace.py   流通交易 API
      ├─ routers/federation.py    联邦任务 API
      ├─ routers/governance.py    治理 API
      ├─ routers/auth.py          用户注册/登录/JWT
      ├─ routers/security.py      安全事件与存证
      └─ routers/agents.py        多智能体编排入口
    数据库（SQLite/PostgreSQL）
      └─ users/data_products/data_transactions/... 12+ 张表

前后端经 REST API 通信（JSON/UTF-8），前端统一经 apiFetch 封装携带 JWT 令牌。

## 第 3 页：系统结构（二）路由模块划分

后端共 20 个路由模块，按功能域划分：

| 功能域 | 路由模块 | 职责 |
|--------|---------|------|
| 流通交易 | marketplace | 产品上架/授权申请/成交/分成/监管看板 |
| 安全存证 | security | 敏感事件记录/审计链生成与校验 |
| 用户权限 | auth / users / admin | 注册登录/JWT/管理员超级面板 |
| 联邦协作 | federation | 任务创建/轮次执行/公平性报告 |
| 治理服务 | governance | PHI 脱敏/结构化/治理报告 |
| 医保智能体 | policy / claims / coverage | 政策问答/报销引擎/待遇查询 |
| 药物智能体 | drugs | 药物相互作用扫描 |
| 健康智能体 | health_profile / body / body_archive | 健康画像/3D人体档案/数字人档案 |
| 专病智能体 | cancer / imaging / eeg | 泛癌筛查/影像分析/脑电分析 |
| 数据智能体 | data / agents | 数据管家/多智能体编排 |

存证链设计：每笔交易/任务结果计算 sha256 摘要，与前一事件哈希串联，
形成不可篡改链式记录；监管方可随时重算验证，篡改即断链。

## 第 4 页：主要功能与操作流程（一）——数据要素流通

演示动线：产品目录 → 交易申请（用途限定）→ 授权成交 → 收益分成 → 审计存证链 → 监管方统计看板。

1. 数据提供方（医院）在"数据要素市场"页上架产品，填写：
   产品名称、提供方、数据类型、样例量、定价、隐私技术标签（联邦学习/差分隐私/脱敏）；
2. 买方（应用智能体或机构）浏览目录，点击"申请授权"，提交用途限定说明；
3. 系统自动成交，按 70%（医院）/ 20%（平台）/ 10%（数据贡献者）三向拆分收益；
4. 成交后页面即时展示最近一笔交易（金额与三向分成明细）：
   金额 ¥{amount}，三向分成：医院 ¥{revenue.provider}、
   平台 ¥{platform}、数据贡献者 ¥{contributor}；
5. 交易摘要（产品/买卖双方/金额/用途）计算哈希入存证链；
6. "交易记录（审计存证链）"区域逐笔列出历史交易及其链上哈希；
7. 全流程无需人工对账，交易记录实时可查。

## 第 5 页：主要功能与操作流程（二）——监管看板

1. 监管方（卫健/数据局视角）在市场页"监管方看板"区域查看指标卡：
   - 累计交易（total_transactions，笔）
   - 流通金额（total_amount，¥）
   - 收益分布（按医院/平台/贡献者三向统计）
   - 产品类型分布（联邦模型/脱敏数据集/统计分析产品）
   - 隐私事件计数与告警
2. 审计存证链校验：输入任意事件，系统用前一事件哈希+摘要重算验证；
3. 敏感操作（导出、跨机构查询）自动记录安全事件（安全中心页集中展示）；
4. 看板数据口径与存证链一致，杜绝账实不符；
5. 页面顶部描述区明示流程：
   "产品目录 → 用途限定授权 → 收益分成（医院70% / 平台20% / 数据贡献者10%）→ 审计存证 → 监管合规"。

## 第 6 页：主要功能与操作流程（三）——用户与权限

1. 用户注册：账号/密码（scrypt 加盐哈希存储，不存明文）；
2. 登录签发 JWT，全站 API 携带令牌鉴权；
3. 角色分为普通用户、医院方、监管方、平台管理员；
4. 管理员超级面板（admin 页）：用户管理、交易审计、系统配置、密钥轮换；
5. 管理员登录独立接口（POST /api/admin/login），返回管理令牌（sha256 计算），
   有效期 24 小时，支持环境变量 ADMIN_USERNAME/ADMIN_PASSWORD 覆盖默认凭据；
6. 未授权访问统一返回 401，敏感操作记录安全事件。

## 第 7 页：主要功能与操作流程（四）——可信数据空间

1. "可信数据空间"页演示"可用不可见"：
   数据需求方看到的是统计结果与模型指标，而非原始记录；
2. 真实事件流展示：数据上架、授权、训练任务、交易等事件按时间线滚动；
3. 联邦协作网络页提供"医院数据全景"（样本量/再入院率/缺失率，
   均为联邦统计口径聚合值，无个体记录）；
4. 三大真实数据引擎验证入口：
   - 联邦引擎：UCI 心脏病 297 例真实患者，三机构非 IID 划分
   - 影像引擎：公开细胞影像数据集
   - EEG 引擎：PhysioNet eegmmiob 真实脑电记录（含 REAL DATA 徽章面板）

## 第 8 页：技术特点（一）

1. **收益分成精确性**：全流程整数分运算（以"分"为单位），规避浮点累加误差；
   分账尾差自动归集到平台方，保证三向分账恒等于交易总额（单元测试覆盖）；
2. **全链路存证**：交易与联邦任务统一 sha256 哈希串联，支持监管方独立重算验证；
3. **多智能体编排**：9 个智能体统一经编排器路由（本地 qwen / 云端 step 双模 LLM，
   治理类请求结构化输出不掉规则层，LLM 不可用时自动降级）；
4. **演示与生产同构**：演示模式离线可用（规则引擎兜底），生产模式接入真实 LLM 与数据库。

## 第 9 页：技术特点（二）

5. **轻量部署**：纯 CPU 可运行；Docker 一键部署；
   已在魔搭创空间公网部署（在线健康检查 /api/health）并以 GitHub Actions 5 分钟保活；
6. **数据安全**：密码 scrypt 加盐哈希；管理员凭据与密钥支持环境变量注入；
   .env 与密钥文件不入代码库（部署打包时显式排除）；
7. **质量保障**：430 项单元测试全绿（pytest）+ 前端 TypeScript 编译零错误，
   覆盖交易分成、存证链、鉴权、智能体路由等核心路径；
8. **真实数据验证**：三大数据引擎均通过真实公开数据集验证
   （UCI 心脏病 AUC 0.9091 / PhysioNet EEG 8 记录 / 公开细胞影像）。

## 第 10 页：使用注意事项

1. 生产环境须完成等保测评与个人信息保护影响评估（PIA）后接入真实数据；
2. 演示数据均为合成数据，不得用于临床诊断；
3. 联邦参与方应签署合作协议，明确数据权属与收益分配（与 70/20/10 分成衔接）；
4. 平台部署后应立即修改默认管理员密码（环境变量 ADMIN_PASSWORD）；
5. 生产部署建议 SQLite 升级为 PostgreSQL 并启用 TLS 传输加密；
6. 医院侧接入前应完成网络隔离评审（专网/VPN），管理端口不对公网开放。
