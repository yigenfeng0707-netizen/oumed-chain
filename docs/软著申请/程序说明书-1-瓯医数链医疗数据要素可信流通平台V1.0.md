## 第 1 页：软件概述

### 1.1 开发目的
医疗数据因安全合规约束难以跨机构流通，导致 AI 模型训练数据不足、数据资产无法变现。本软件开发目的：
1. 为医疗机构提供"原始数据不出院、数据价值可流通"的数据要素交易基础设施；
2. 建立数据产品目录、授权交易、收益分成、审计存证的完整闭环；
3. 为监管方提供实时监管看板，满足《数据安全法》《个人信息保护法》合规要求；
4. 承载多智能体医疗应用生态（9 个智能体），形成数据消费侧的规模化需求。

### 1.2 主要功能
数据产品目录管理、数据要素授权交易与收益分成（70/20/10）、审计存证链（sha256 哈希串联）、监管合规看板、用户与权限管理、多智能体医疗应用生态（医保政策问答、报销引擎、药物相互作用扫描、健康画像、3D 人体档案、泛癌筛查、影像分析、EEG 脑电分析、数据管家）。

### 1.3 运行环境
- 硬件：4 核 CPU / 8GB 内存起
- 操作系统：Windows 10+ / Ubuntu 22.04+ / 信创环境
- 支撑软件：Python 3.11+、Node.js 20+、PostgreSQL 16（或 SQLite）
- 开发语言：Python（FastAPI 后端）、TypeScript（React/Next.js 前端）

## 第 2 页：系统结构（一）

平台采用前后端分离架构：

    前端（Next.js 14 / React 18 / TypeScript）
      ├─ 数据要素市场页   产品目录/交易记录/监管看板
      ├─ 联邦协作网络页   任务发起/收敛曲线/逐院公平性/存证链
      ├─ AI病历治理页     病历输入/脱敏对比/结构化结果
      ├─ 可信数据空间页   可用不可见演示/真实事件流
      └─ 多智能体应用页   医保问答/报销/药物扫描/健康画像等 9 个应用
    后端（FastAPI / Python 3.11）
      ├─ routers/marketplace.py   流通交易 API
      ├─ routers/federation.py    联邦任务 API
      ├─ routers/governance.py    治理 API
      ├─ routers/auth.py          用户注册/登录/JWT
      ├─ routers/security.py      安全事件与存证
      └─ routers/agents.py        多智能体编排入口
    数据库（SQLite/PostgreSQL）
      └─ users/data_products/data_transactions/... 12+ 张表

## 第 3 页：系统结构（二）

后端共 20 个路由模块，按功能域划分：

| 功能域 | 路由模块 | 职责 |
|--------|---------|------|
| 流通交易 | marketplace | 产品上架/授权申请/成交/分成/监管看板 |
| 安全存证 | security | 敏感事件记录/审计链生成与校验 |
| 用户权限 | auth / users / admin | 注册登录/JWT/管理员超级面板 |
| 联邦协作 | federation | 任务创建/轮次执行/公平性报告 |
| 治理服务 | governance | PHI 脱敏/结构化/治理报告 |
| 智能体 | agents / claims / drugs / policy / health_profile / body / body_archive / cancer / imaging / eeg / data | 9 个医疗智能体应用 |

存证链设计：每笔交易/任务结果计算 sha256 摘要，与前一事件哈希串联，形成不可篡改链式记录；监管方可随时重算验证，篡改即断链。

## 第 4 页：主要功能与操作流程（一）——数据要素流通

1. 数据提供方（医院）在"数据要素市场"页上架产品，填写：产品名称、提供方、数据类型、样例量、定价、隐私技术标签（联邦学习/差分隐私/脱敏）；
2. 买方（应用智能体或机构）浏览目录，点击"申请授权"，提交用途限定说明；
3. 系统自动成交，按 70%（医院）/ 20%（平台）/ 10%（数据贡献者）三向拆分收益，金额精确到分（整数分运算，避免浮点截断）；
4. 交易摘要（产品/买卖双方/金额/用途）计算哈希入存证链；
5. 全流程无需人工对账，交易记录实时可查。

## 第 5 页：主要功能与操作流程（二）——监管看板

1. 监管方登录后进入监管看板，实时查看：
   - 累计交易笔数、流通总金额；
   - 收益分布（按医院/平台/贡献者三向统计）；
   - 产品类型分布（联邦模型/脱敏数据集/统计分析产品）；
   - 隐私事件计数与告警；
2. 审计存证链校验：输入任意事件，系统用前一事件哈希+摘要重算验证；
3. 敏感操作（导出、跨机构查询）自动记录安全事件；
4. 看板数据口径与存证链一致，杜绝账实不符。

## 第 6 页：主要功能与操作流程（三）——用户与权限

1. 用户注册：账号/密码（scrypt 加盐哈希存储，不存明文）；
2. 登录签发 JWT，全站 API 携带令牌鉴权；
3. 角色分为普通用户、医院方、监管方、平台管理员；
4. 管理员超级面板：用户管理、交易审计、系统配置、密钥轮换；
5. 管理员登录独立接口，令牌有效期 24 小时，支持环境变量覆盖默认凭据。

## 第 7 页：技术特点（一）

1. **收益分成精确性**：全流程整数分运算（以"分"为单位），规避浮点累加误差；分账尾差自动归集到平台方，保证三向分账恒等于交易总额；
2. **全链路存证**：交易与联邦任务统一 sha256 哈希串联，支持监管方独立重算验证；
3. **多智能体编排**：9 个智能体统一经编排器路由（本地 qwen / 云端 step 双模 LLM，治理类请求结构化输出不掉规则层）；
4. **演示与生产同构**：演示模式离线可用（规则引擎兜底），生产模式接入真实 LLM 与数据库。

## 第 8 页：技术特点（二）

5. **轻量部署**：纯 CPU 可运行；Docker 一键部署；已在魔搭创空间公网部署并 5 分钟保活；
6. **数据安全**：敏感字段传输加密；管理员密码与密钥支持环境变量注入；.env 不入库；
7. **质量保障**：427+ 项单元测试全绿，覆盖交易分成、存证链、鉴权等核心路径；
8. **真实数据验证**：平台三大数据引擎（联邦/影像/EEG）均通过真实公开数据集验证（UCI 心脏病 AUC 0.9091 / PhysioNet EEG 8 记录 / 细胞影像）。

## 第 9 页：使用注意事项

1. 生产环境须完成等保测评与个人信息保护影响评估后接入真实数据；
2. 演示数据均为合成数据，不得用于临床诊断；
3. 联邦参与方应签署合作协议明确数据权属与收益分配；
4. 平台部署后应立即修改默认管理员密码（环境变量 ADMIN_PASSWORD）。
