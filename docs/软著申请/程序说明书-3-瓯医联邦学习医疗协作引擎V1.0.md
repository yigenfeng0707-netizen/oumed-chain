## 第 1 页：软件概述

### 1.1 开发目的
单一医院病例量有限，AI 模型难以达到可用精度；集中汇总各院数据又违反
《个人信息保护法》《数据安全法》。本软件开发目的：
1. 让多家医院在原始数据不出院的前提下联合训练临床风险模型（心衰再入院风险预测）；
2. 提供联邦统计标准化能力，跨院分布差异不打偏模型；
3. 以差分隐私分级保护上传的模型参数，防止梯度反演泄露个体信息；
4. 输出逐院公平性评估，确保协作对每家参与医院都有增益；
5. 任务结果审计存证上链，训练过程可审计可复现。

### 1.2 主要功能
多机构联邦学习任务编排（FedAvg 加权聚合）、差分隐私分级保护
（DP-FedAvg 裁剪 + 高斯噪声，σ 三档）、联邦统计标准化（矩信息聚合）、
任务结果审计存证上链（sha256 哈希串联）、逐院公平性评估报告、
隐私-效用权衡可视化、真实数据集验证（UCI 心脏病 297 例三机构非 IID 划分）。

### 1.3 运行环境
- 硬件：4 核 CPU / 8GB 内存（无需 GPU，12 轮训练全流程约 94ms）
- 操作系统：Windows 10+ / Ubuntu 22.04+ / 信创环境适配
- 支撑软件：Python 3.11+、NumPy、pandas、scikit-learn
- 开发语言：Python 3.13；前端展示 TypeScript（React 18 / Next.js 14）

## 第 3 页：主要功能与操作流程（一）——发起联邦训练

1. 管理员进入"联邦协作网络"页，首先查看"医院数据全景"：
   三家医院各自的样本量、再入院率、缺失率——均为联邦统计口径聚合值，
   无任何个体记录；
2. 在任务配置面板设置参数：
   - 联邦轮次（slider，默认 12，范围 1-50）；
   - 本地 Epoch（slider，默认 3，范围 1-20）；
   - 差分隐私档位（下拉：关闭 / σ=0.01 轻噪声（推荐） /
     σ=0.03 中噪声 / σ=0.08 强噪声）；
3. 点击"发起联邦训练"（运行中按钮切换"联邦训练中…"），
   系统执行：联邦统计标准化 → 各院本地训练 → 参数上传（差分隐私加噪）
   → 服务器加权聚合（FedAvg）→ 循环至收敛；
4. 输出：AUC 收敛曲线（逐轮绘制）、最终 AUC、逐院公平性对比；
5. 12 轮全流程约 94ms（纯 CPU），支持现场演示与交互式调参。

## 第 4 页：主要功能与操作流程（二）——联邦统计标准化

1. 训练前各院上报标准化所需矩信息：样本量 n、特征和 sum、
   特征平方和 sum_sq（三者均为聚合统计量，不含个体记录）；
2. 服务器聚合矩信息计算全局均值与方差，生成各院标准化参数；
3. 各院本地应用标准化，消除跨院量纲与分布差异；
4. 矩信息无法还原个体数据（n 条记录聚合为 3 个统计量，
   信息论上不可逆）；
5. 该机制解决非 IID 场景下"某院分布偏斜打偏全局模型"的经典问题：
   合成数据生成器按机构差异化分布（模拟真实跨院患者结构差异），
   标准化后联邦模型收敛显著快于无标准化基线。

## 第 5 页：主要功能与操作流程（三）——差分隐私与公平性

1. 差分隐私（DP-FedAvg）：客户端模型更新先做 L2 范数裁剪
   （限制单样本对全局参数的影响上限），再加高斯噪声；
2. σ 档位设计（前端可选，权衡可视化）：
   - σ=0.01 轻噪声（推荐）：AUC 损失约 1% 内，隐私保护入门级
   - σ=0.03 中噪声：AUC 损失约 2-4%，中等保护
   - σ=0.08 强噪声：AUC 损失明显，高保护场景
3. "隐私-效用权衡"图四柱对比（无隐私/σ=0.01/0.03/0.08），
   训练前后 AUC 变化实时呈现，为隐私预算决策提供数据支撑；
4. 逐院公平性评估：对每家参与医院分别计算
   "仅用本院数据训练的本地模型 AUC"与"联邦模型在本院测试集 AUC"；
5. 公平性报告输出逐院对比表：联邦模型应使每院 AUC
   不低于本地基线（协作普惠性）；若某院无增益则标注提示。

## 第 6 页：主要功能与操作流程（四）——审计存证链

1. 每个联邦任务完成后，系统计算任务结果摘要（最终参数/AUC/配置）的
   sha256 哈希；
2. 哈希与前一任务哈希串联，形成链式存证（与流通平台交易链同构）；
3. 前端"最近任务存证链"区域逐任务展示链上记录，
   悬停提示任务参数（如"12轮 σ=0.01"）；
4. 审计方可用前一哈希 + 摘要重算验证任意任务记录，
   篡改任何一环即导致后续全链校验失败；
5. 存证同时记录任务配置（轮次/Epoch/σ），保证训练可复现。

## 第 7 页：技术特点（一）

1. **真实数据验证**：UCI 心脏病数据集 297 例真实患者，
   按机构划分三份非 IID 子集，联邦 AUC 0.9091 追平集中式上界 0.9019
   ——验证引擎在真实数据上的有效性（非仅合成数据演示）；
2. **隐私-效用量化**：σ 三档实测 AUC 损失可视，
   为医院隐私预算决策提供数据支撑；
3. **存证上链**：任务结果 sha256 串联，训练过程可审计可复现，
   与流通平台交易存证同构（一套链验证两类事件）；
4. **公平性可验证**：逐院 AUC 对比机制确保协作对所有参与方有增益，
   而非牺牲弱院成全强院——这是医院愿意参与协作的前提。

## 第 8 页：技术特点（二）

5. **轻量实时**：12 轮联邦训练全流程约 94ms（纯 CPU），
   支持现场演示与交互式调参，无 GPU 依赖；
6. **非 IID 建模**：合成数据生成器（data_generator）按机构差异化分布，
   联邦统计标准化针对性校正，逼近真实跨院协作难度；
7. **纯 Python 自研**：不依赖 TensorFlow Federated / FedML 等重型框架，
   NumPy + scikit-learn 自研聚合（fed_average）与训练逻辑
   （LogisticModel），代码全量可审计、便于信创移植；
8. **质量保障**：联邦统计 / FedAvg / 差分隐私 / 公平性评估
   均有单元测试覆盖（含非 IID 划分与 DP 档位组合用例）。

## 第 9 页：使用注意事项

1. 生产部署须升级为跨院网络拓扑（各院独立节点 + mTLS 通信），
   本 V1.0 为单机模拟编排（逻辑与跨院一致，通信层待生产化）；
2. 差分隐私正式使用前应完成隐私预算核算
   （RDP / 矩会计，输出精确 ε, δ），当前 σ 档位为工程近似；
3. 联邦参与方应签署合作协议，明确数据权属与收益分配
   （与流通平台 70/20/10 分成衔接）；
4. 模型输出用于临床决策支持，不替代医生诊断；
5. 参与医院数据质量（缺失率/样本量）应在准入时评估，
   过低质量院方可能无协作增益。
