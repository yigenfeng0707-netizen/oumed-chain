## 第 1 页：软件概述

### 1.1 开发目的
医疗机构积累大量非结构化电子病历文本，其中包含身份证号、手机号、患者姓名等
个人敏感信息（PHI），未经治理无法用于科研训练、模型开发或数据流通。本软件开发目的：
1. 自动识别病历文本中的 PHI 敏感实体并脱敏，保留临床语义；
2. 将非结构化病历自动结构化为标准化数据（患者/主诉/诊断/体征/用药/既往史）；
3. 生成治理报告，使病历数据达到可流通、可交易的合规状态；
4. 全流程支持本地大模型推理（数据不出院），满足院内合规要求。

### 1.2 主要功能
PHI 敏感实体识别与脱敏（身份证/手机号/座机/住院号/银行卡/邮箱/姓名）、
本地大模型病历结构化、云端大模型结构化、规则引擎结构化兜底、
治理流水线编排（三级降级链）、治理报告输出（脱敏文本/实体清单/结构化数据/流水线记录）。

### 1.3 运行环境
- 硬件：4 核 CPU / 8GB 内存（本地大模型推理建议 16GB）
- 操作系统：Windows 10+ / Ubuntu 22.04+ / 信创环境适配
- 支撑软件：Python 3.11+、FastAPI、Ollama（可选，本地推理 qwen3:4b）、
  云端 LLM API（可选）、Node.js 20+（前端）
- 开发语言：Python 3.13（后端）、TypeScript（React 18 / Next.js 14 前端）

## 第 3 页：主要功能与操作流程（一）——PHI 脱敏

1. 用户进入"AI 病历治理"页，粘贴非结构化入院记录；
   不便手动输入时点击"填入示例病历"载入内置演示病历；
2. 点击"一键治理"，按钮切换为"治理中（本地推理约10-60秒）…"，
   系统首先执行 PHI 脱敏（规则引擎）：
   a. 身份证号：18 位规则匹配，掩码替换；
   b. 手机号：11 位规则匹配，保留前三后四（138****5678）；
   c. 座机 / 住院号 / 银行卡 / 邮箱：对应正则识别掩码；
   d. 患者姓名：语境识别（"患者张三"句式），保留姓氏掩名（张*）；
3. 脱敏输出：掩码文本 + 敏感实体清单（类型 / 位置 / 掩码方式）；
4. 前端以"脱敏对比"双栏视图展示原文与脱敏后文本，
   敏感片段高亮标注，逐条对应实体清单；
5. 保留姓氏与临床语义，确保脱敏后文本仍可用于模型训练。

## 第 4 页：主要功能与操作流程（二）——结构化

1. 脱敏完成后自动进入结构化阶段，三级引擎依次尝试：
   a. 本地大模型（Ollama qwen3:4b，院内网推理，数据不出院）；
   b. 云端大模型（结构化提示词约束输出 JSON）；
   c. 规则引擎（正则 + 关键词抽取，无 LLM 依赖）；
2. 输出标准化 JSON，字段包括：
   - 患者信息（性别 / 年龄）
   - 主诉（症状描述与持续时间）
   - 诊断（主诊断与合并症）
   - 生命体征（血压 / 心率 / 体温，自动清洗数值与单位）
   - 用药（药名 / 剂量 / 频次）
   - 既往史（慢性病 / 手术史 / 过敏史）
3. 结构化调用参数：temperature=0.1（降低随机性），
   输入截断 3000 字符（控制 token 成本），超时 90 秒；
4. JSON 提取容错：模型输出含代码块 / 前后缀文本时自动剥离
   （_extract_json_block / _extract_json 双重提取）；
5. 结构化结果以表格视图展示，字段缺失单元格明确标注而非留空。

## 第 5 页：主要功能与操作流程（三）——治理报告

1. 治理完成后系统输出治理报告，包含四部分：
   - 脱敏文本（掩码后全文，可直接用于训练 / 流通）；
   - 敏感实体清单（逐条：类型 / 原文片段 / 掩码方式 / 位置）；
   - 结构化数据集（标准化 JSON，即"可上架"的数据产品形态）；
   - 流水线记录（各阶段耗时 / 使用的引擎 / 降级路径）；
2. 报告可作为数据产品上架"数据要素市场"的合规凭证，
   与平台侧（瓯医数链流通平台）的 70/20/10 收益分成衔接；
3. 治理失败时报告标注降级原因（如本地模型不可用 → 已切换云端 / 规则），
   流水线不中断，始终产出可用结果；
4. 弱格式 PHI（姓名 / 住址）在报告中标注"建议人工复核"。

## 第 6 页：技术特点（一）

1. **三级降级链**：本地大模型失败自动切换云端，云端失败降级规则引擎，
   系统永不中断（每级失败均被捕获并记录降级路径）；
2. **PHI 识别精度**：身份证 / 手机号等强格式实体正则精确匹配；
   姓名语境识别处理中文病历典型句式（"患者某某" / "某某，男，65岁"）；
3. **脱敏保语义**：掩码保留姓氏与临床关键词，脱敏后文本仍具训练价值；
4. **数据不出院**：本地 Ollama 推理模式全程院内网完成，无外传；
   云端模式仅在本地不可用且用户明确允许时启用。

## 第 7 页：技术特点（二）

5. **结构化输出约束**：提示词强制 JSON schema，temperature=0.1 降低随机性，
   _extract_json 双重容错剥离模型输出杂质；
6. **字段自动清洗**：血压"140/90mmHg"等字段自动抽取数值与单位；
   年龄"65岁"自动剥离单位转数值；
7. **轻量部署**：纯规则模式零 LLM 依赖，CPU 即可运行；
   Docker 与主平台一体化部署；
8. **质量保障**：脱敏规则、结构化字段、降级路径均有单元测试覆盖
   （含本地 / 云端 / 规则三模式与失败注入用例）。

## 第 8 页：使用注意事项

1. 本系统治理后的病历用于科研 / 训练 / 流通，不得用于临床诊断；
2. 生产环境建议启用本地 Ollama 推理（数据不出院），
   云端模式需完成合规评估（数据出域审批）；
3. 姓名 / 住址等弱格式 PHI 建议人工复核脱敏结果；
4. 治理报告与原始病历应分开存储，原始病历保留在院内；
5. 大规模批量治理建议夜间批处理（本地推理约 10-60 秒/份）；
6. 结构化结果入库前应执行字段完整性校验。

## 第 9 页：运行环境与部署补充说明

1. 配置项（环境变量 / .env，均可按部署环境注入）：
   - LLM_BASE_URL：大模型推理入口（云端 API 地址，或本地 Ollama 服务地址）；
   - LLM_API_KEY：云端模型密钥（本地 Ollama 模式下可置空）；
   - LLM_MODEL：结构化所用模型名称；
   - 本地模式将 LLM_BASE_URL 指向院内 Ollama 服务（qwen3:4b），
     推理全程院内网完成，实现"数据不出院"；
2. 部署形态：
   - 与主平台（瓯医数链流通平台）一体化 Docker 部署，
     治理服务随平台容器启动，无需独立部署；
   - 纯规则模式零外部依赖，CPU 环境即可完成 PHI 脱敏与规则结构化；
3. 性能参考（单份病历，含结构化全流程）：
   - 本地 Ollama 推理约 10-60 秒（视硬件而定）；
   - 规则引擎兜底路径毫秒级完成；
4. 质量验证：pytest 覆盖脱敏规则、结构化字段清洗、
   三级降级路径与失败注入用例，随主平台 430 项测试统一运行。
