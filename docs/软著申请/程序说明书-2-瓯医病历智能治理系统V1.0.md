## 第 1 页：软件概述

### 1.1 开发目的
医疗机构积累大量非结构化电子病历文本，其中包含身份证号、手机号、患者姓名等个人敏感信息（PHI），未经治理无法用于科研训练、模型开发或数据流通。本软件开发目的：
1. 自动识别病历文本中的 PHI 敏感实体并脱敏，保留临床语义；
2. 将非结构化病历自动结构化为标准化数据（患者/主诉/诊断/体征/用药/既往史）；
3. 生成治理报告，使病历数据达到可流通、可交易的合规状态。

### 1.2 主要功能
PHI 敏感实体识别与脱敏（身份证/手机号/座机/住院号/银行卡/邮箱/姓名）、本地大模型病历结构化、规则引擎结构化兜底、治理流水线编排、治理报告输出。

### 1.3 运行环境
- 硬件：4 核 CPU / 8GB 内存（本地大模型推理建议 16GB）
- 操作系统：Windows 10+ / Ubuntu 22.04+ / 信创环境
- 支撑软件：Python 3.11+、Ollama（可选，本地推理 qwen3:4b）、云端 LLM API（可选）
- 开发语言：Python 3.13（FastAPI）、TypeScript（React 18）

## 第 2 页：系统结构

    前端（Next.js 14）
      └─ AI病历治理页 page.tsx
           ├─ 病历输入区（粘贴/载入示例）
           ├─ 一键治理按钮
           ├─ 脱敏对比视图（原文 vs 脱敏后，敏感片段高亮）
           └─ 结构化结果视图（标准化 JSON 表格展示）
    后端（FastAPI）
      ├─ routers/governance.py    治理 API（POST /api/governance）
      └─ services/governance.py   治理引擎
            ├─ deidentify()      PHI 脱敏（正则规则引擎）
            ├─ llm_structure()   LLM 结构化（本地→云端→失败降级）
            ├─ rule_structure()  规则结构化（兜底）
            └─ govern()          治理流水线编排

核心数据结构：DeidResult（脱敏结果：脱敏文本+敏感实体清单）。

## 第 3 页：主要功能与操作流程（一）——PHI 脱敏

1. 用户进入"AI 病历治理"页，粘贴非结构化入院记录（或点击"载入示例"）；
2. 点击"一键治理"，系统首先执行 PHI 脱敏（规则引擎）：
   a. 身份证号：18 位规则匹配，掩码替换；
   b. 手机号：11 位规则匹配，保留前三后四（138****5678）；
   c. 座机/住院号/银行卡/邮箱：对应正则识别掩码；
   d. 患者姓名：语境识别（"患者张三"句式），保留姓氏掩名（张*）；
3. 脱敏输出：掩码文本 + 敏感实体清单（类型/位置/掩码方式）；
4. 保留姓氏与临床语义，确保脱敏后文本仍可用于模型训练。

## 第 4 页：主要功能与操作流程（二）——结构化

1. 脱敏完成后自动进入结构化阶段，三级引擎依次尝试：
   a. 本地大模型（Ollama qwen3:4b，院内网推理，数据不出院）；
   b. 云端大模型（结构化提示词约束输出 JSON）；
   c. 规则引擎（正则+关键词抽取，无 LLM 依赖）；
2. 输出标准化 JSON：患者信息、主诉、诊断、生命体征（血压等自动清洗）、用药、既往史；
3. 结构化提示词 temperature=0.1，输入截断 3000 字符，超时 90 秒；
4. JSON 提取容错：模型输出含代码块/前后缀文本时自动剥离。

## 第 5 页：主要功能与操作流程（三）——治理报告

1. 治理完成后系统输出治理报告，包含四部分：
   - 脱敏文本（掩码后全文）；
   - 敏感实体清单（逐条：类型/原文片段/掩码方式）；
   - 结构化数据集（标准化 JSON）；
   - 流水线记录（各阶段耗时/使用的引擎/降级路径）；
2. 报告可导出，作为数据产品上架"数据要素市场"的合规凭证；
3. 治理失败时报告标注降级原因（如本地模型不可用），流水线不中断。

## 第 6 页：技术特点（一）

1. **双引擎容错**：本地大模型失败自动切换云端，云端失败降级规则引擎，系统永不中断（三级降级链）；
2. **PHI 识别精度**：身份证/手机号等强格式实体正则精确匹配；姓名语境识别处理中文病历典型句式；
3. **脱敏保语义**：掩码保留姓氏与临床关键词，脱敏后文本仍具训练价值；
4. **数据不出院**：本地 Ollama 推理模式全程院内网完成，无外传。

## 第 7 页：技术特点（二）

5. **结构化输出约束**：提示词强制 JSON schema，temperature=0.1 降低随机性，_extract_json 容错剥离模型输出杂质；
6. **字段自动清洗**：血压"140/90mmHg"等字段自动抽取数值与单位；
7. **轻量部署**：纯规则模式零 LLM 依赖，CPU 即可运行；
8. **质量保障**：脱敏与结构化均有单元测试覆盖（含降级路径测试）。

## 第 8 页：使用注意事项

1. 本系统治理后的病历用于科研/训练/流通，不得用于临床诊断；
2. 生产环境建议启用本地 Ollama 推理（数据不出院），云端模式需完成合规评估；
3. 姓名/住址等弱格式 PHI 建议人工复核脱敏结果；
4. 治理报告与原始病历应分开存储，原始病历保留在院内。
