## 一、软件概述

### 1.1 开发目的
医疗数据因安全合规约束难以跨机构流通，导致 AI 模型训练数据不足、数据资产无法变现。本软件开发目的：
1. 让多家医院在原始数据不出院的前提下联合训练临床风险模型；
2. 自动完成病历脱敏与结构化治理，产出可流通的合规数据产品；
3. 提供数据产品目录、授权交易、收益分成与监管看板的完整流通基础设施。

### 1.2 主要功能（对应三件软著划分）
| 件 | 软件名称 | 核心功能 |
|----|---------|---------|
| 1 | 瓯医数链医疗数据要素可信流通平台 | 数据产品目录、授权交易、收益分成、审计存证、监管看板、多智能体应用生态 |
| 2 | 瓯医病历智能治理系统 | PHI 识别脱敏、本地大模型病历结构化、规则兜底、治理报告 |
| 3 | 瓯医联邦学习医疗协作引擎 | 联邦任务编排、FedAvg 聚合、差分隐私、联邦统计、公平性评估 |

### 1.3 运行环境
- 硬件：4 核 CPU / 8GB 内存起（本地大模型推理建议 16GB）
- 操作系统：Windows 10+ / Ubuntu 22.04+ / 信创环境适配
- 支撑软件：Python 3.11+、Node.js 20+、PostgreSQL 16（或 SQLite）、Ollama（可选，本地推理）
- 开发语言：Python 3.13、TypeScript（React 18）

## 二、系统结构

```
前端（Next.js 14）
  ├─ 联邦协作网络页   任务发起/收敛曲线/逐院公平性/存证链
  ├─ AI病历治理页     病历输入/脱敏对比/结构化结果
  ├─ 数据要素市场页   产品目录/交易记录/监管看板
  └─ 可信数据空间页   可用不可见演示/真实事件流
后端（FastAPI）
  ├─ routers/federation.py    联邦任务 API
  ├─ routers/governance.py    治理 API
  ├─ routers/marketplace.py   流通交易 API
  ├─ services/federated/      联邦引擎（数据生成/FedAvg/差分隐私）

  └─ users/federation_jobs/data_products/data_transactions/... 12+ 张表
```

## 三、主要功能与操作流程

### 3.1 联邦学习协作（件三）
1. 管理员进入"联邦协作网络"页，查看三家医院数据全景（样本量、再入院率、缺失率——联邦统计口径，无个体记录）
2. 配置任务参数：联邦轮次（1-50）、本地 Epoch（1-20）、差分隐私档位（关闭/σ=0.01/0.03/0.08）
3. 点击"发起联邦训练"，系统执行：联邦统计标准化 → 各院本地训练 → 参数上传 → 服务器加权聚合（FedAvg）→ 循环至收敛
4. 输出：AUC 收敛曲线、最终 AUC、逐院公平性对比（本院本地模型 vs 联邦模型）
5. 任务结果自动计算存证哈希（sha256），与前一任务哈希串联入链

### 3.2 病历治理（件二）
1. 进入"AI病历治理"页，粘贴非结构化入院记录（或载入示例）
2. 点击"一键治理"，流水线执行：
   a. PHI 脱敏（规则引擎）：身份证/手机号/座机/住院号/银行卡/邮箱正则识别 + 姓名语境识别，敏感片段以█掩码，保留姓氏与临床语义
   b. 结构化（本地大模型 qwen3:4b，院内网推理）：输出患者/主诉/诊断/生命体征/用药/既往史标准化 JSON；血压等字段自动清洗
   c. 大模型不可用时自动降级规则抽取，系统不中断
3. 输出治理报告：脱敏文本、敏感实体清单、结构化数据集、流水线记录

### 3.3 数据要素流通（件一）
1. 数据提供方在"数据要素市场"上架产品（名称/提供方/类型/样例量/定价/隐私技术标签）
2. 买方（应用智能体或机构）点击"申请授权"，提交用途限定
3. 系统自动成交并按 70%/20%/10% 拆分收益（医院/平台/数据贡献者）
4. 交易摘要入存证链；监管方看板实时统计交易笔数、流通金额、收益分配、隐私事件

### 3.4 监管合规
1. 监管方打开看板查看：累计交易、流通金额、收益分布、产品类型分布
2. 审计存证链校验：任意事件哈希可用前一哈希+摘要重算验证，篡改即断链
3. 隐私事件监控：平台实时计数并告警

## 四、技术特点
1. 联邦统计：标准化所需矩信息（n/sum/sum_sq）聚合，原始数据不出院
2. 差分隐私分级：客户端更新裁剪+高斯噪声（DP-FedAvg），σ 分档可视
3. 双引擎容错：本地大模型失败自动切换规则引擎
4. 全链路存证：任务与交易统一哈希串联，支持监管校验
5. 轻量部署：纯 CPU 可运行；Docker Compose 一键部署；演示模式离线可用

## 五、使用注意事项
1. 生产环境须完成等保测评与个人信息保护影响评估后接入真实数据
2. 演示数据均为合成数据，不得用于临床诊断
3. 联邦参与方应签署合作协议明确数据权属与收益分配
