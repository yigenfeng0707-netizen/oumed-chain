## 演练发现并修复的真实问题（3 项生产代码修复 + 1 项部署脚本教训）

1. **moments 并发竞态（P0 级生产 bug）**：两节点并发上传联邦统计时各自读到对方未提交的 existing → 双方均判"未集齐" → 任务永久卡死 collecting（演练两次超时复现，DB 证据：两条 moments 间隔 2.4ms）。
   修复：`federation_nodes.py` upload_moments 先提交再重读 + 原子 UPDATE 抢占聚合权（`WHERE status='collecting'`，rowcount≠1 幂等跳过）。修复后场景 1 稳定 ~11s 完成。
2. **Agent 网络零重试**：一次瞬时抖动（拒连/重置）即杀死节点进程，违背断点续训语义（演练中平台重启窗口节点全灭）。
   修复：`node_agent/main.py` `_api` 网络异常归一化 ConnectionError + `_api_retry` 指数退避（1s 起步翻倍封顶 15s，最长 15 分钟；POST 靠平台 409 幂等语义保证重试安全；401 类凭证错误不重试直接退出）。
3. **mTLS 证书链扩展缺失**：演练 CA 证书无 `keyUsage` 扩展，Python ssl（OpenSSL 3.x）验签直接失败（`CA cert does not include key usage extension`），三场景全拒。
   修复：演练 CA 生成补 `basicConstraints=critical,CA:TRUE` + `keyUsage=critical,keyCertSign,cRLSign`，叶子证书补 keyUsage+CA:FALSE。**部署脚本教训**：`deploy/tls/gen-certs.sh` 需保证同样的扩展集合，否则生产 nginx mTLS 会被新版本 OpenSSL 客户端全量拒绝。
4. **openssl 便携发行版兼容**：Strawberry/conda 版 openssl 的 OPENSSLDIR 指向不存在盘导致 `req` 必失败；编排脚本改为真实签发探活自动定位可用二进制（Git mingw64 验证通过，含中文路径）。

## 演练工程备忘（编排脚本侧，非生产代码）

- HTTPS 平台健康检查必须携带联邦客户端证书（CERT_REQUIRED 平台每条连接都要证书），且显式构造无代理 opener（系统代理会劫持 loopback mTLS 请求）。
- TLS 1.3 客户端握手先于服务端证书校验完成：无证书/野证书被拒的表现是握手成功后服务端零数据断连，判定逻辑按"是否收到 HTTP 响应行"分类。
- 子进程凭证/证书路径一律经环境变量传递——中文路径嵌入 `python -c` 代码串会被转义序列（如 `\backend` 的 `\b`）破坏，曾致子进程 `OSError: Errno 22` 崩溃（stdout 空、stderr 未采集的静默失败）。
