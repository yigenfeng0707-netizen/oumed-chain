# 瓯医数链 OuMedTrust — 商业计划书（初赛版）

> 第二届全球技术创新大赛 · AI+医疗专题赛（赛道二：医疗大模型与数据）
> 医疗数据要素可信流通平台：让医疗数据「可用不可见、可控可计量」

---

## 一、项目概述

瓯医数链是一个**医疗数据要素可信流通平台**：以联邦学习实现医院间"数据不出院"联合建模，以本地大模型实现病历自动治理与 PHI 脱敏，以差分隐私与审计存证链保障全程合规，并打通数据产品目录、授权交易、收益分成与监管看板的完整闭环。

**一句话定位**：医疗数据界的" trustworthy 数据交易所 + 治理工厂"，让沉睡在医院服务器里的数据，变成可确权、可定价、可流通、可监管的数据要素。

**产品形态**：1 个可信数据底座（联邦协作 × AI 治理 × 流通交易 × 监管合规）+ N 个医疗 AI 应用生态（健康卫士、影像卫士、档案管家、泛癌卫士等 9 个智能体作为数据消费方与民生出口。其中泛癌卫士直接承载温附医附属第一医院发表于 Cell（2026）的 Oncoformer 泛癌预测模型——医院数据不出院、模型作为数据产品在平台流通的标杆案例）。

---

## 二、痛点与政策机遇

**三重痛点**：
1. **医院不敢共享**：医疗数据敏感、权属模糊，传统"数据大池化"模式面临《数据安全法》《个人信息保护法》硬约束——数据不敢动，AI 模型吃不到跨院数据
2. **数据不会增值**：基层医院数据质量参差（特征缺失 12%-32%），单院建模 AUC 仅 0.69，数据资产无法变现，医院缺乏参与动力
3. **流通没有基础设施**：数据产品如何定价、如何授权、如何分成、如何监管——缺乏"可用不可见"的技术底座与合规流程

**政策机遇（精准卡位）**：
- "数据要素×医疗健康"为国家数据局重点行动方向；浙江省是数据要素市场化配置改革试点
- 本赛道主办方第一名为**温州市经济和信息化局**——数据要素正是其核心 KPI
- 中国（温州）智能谷定位数字经济，医疗数据要素平台是天然的落地载体

## 三、解决方案：四层架构闭环

```
┌─ 应用层 ─┐  健康卫士/影像卫士/政策参谋/泛癌卫士等 9 个医疗智能体（数据消费方）
├─ 流通层 ─┤  数据产品目录 → 用途限定授权 → 交易结算 → 收益分成 70/20/10
├─ 协作层 ─┤  联邦学习（数据不出院联合建模）+ AI 病历治理（脱敏+结构化）
└─ 合规层 ─┘  差分隐私 + 审计存证链（sha256 串联）+ 监管方实时看板
```

**闭环故事**（演示动线）：社区卫生中心的病历经 AI 治理 Copilot 脱敏结构化 → 上架数据要素市场 → 联邦任务消费三院数据训练风险模型（AUC 追平集中训练上界）→ 模型作为数据产品被健康卫士 Agent 授权采购 → 每一笔交易自动存证上链 → 监管方看板实时可见：流通金额、收益分配、隐私事件 0 起。

---

## 四、核心技术创新（全部真实现，现场可运行）

1. **轻量联邦学习引擎**（自研，纯 CPU）：FedAvg + 差分隐私（DP-FedAvg 裁剪+高斯噪声）+ 联邦统计。**实测：三家异构医院（三甲 4200 例/县医院 2400 例/社区 1100 例，特征缺失率 5%-22%）联邦后全局 AUC 0.7018，追平数据大池化集中训练上界 0.7012**；逐院公平性全部获益，基层获益最大
2. **AI 病历治理 Copilot**（本地 qwen3:4b，院内网推理）：非结构化病历 → 结构化 JSON（患者/主诉/诊断/生命体征/用药/既往史 7 字段），PHI 脱敏规则引擎识别身份证/手机号/姓名/住院号四类实体零漏检；LLM 失效自动降级规则引擎，**系统永不宕机**
3. **审计存证链**：每个联邦任务与交易的摘要 sha256 串联上链，任何篡改导致链条断裂，监管方一键校验
4. **数据要素交易引擎**：产品目录 → 用途限定授权 → 收益分成（医院 70%/平台 20%/数据贡献者 10%）→ 监管统计，隐私事件实时监控

**工程底座**：FastAPI + Next.js 14 全栈，448 个单元测试（含生产鉴权与越权审计回归），CI/CD，三级降级容错（本地模型→云端 API→规则引擎），Docker Compose 一键部署。

## 五、实验验证（种子固定，可复现）

| 方案 | 全局测试 AUC |
|------|-------------|
| 三甲医院本地模型 | 0.7013 |
| 县医院本地模型 | 0.6994 |
| 社区中心本地模型 | 0.6896 |
| **联邦学习 FedAvg** | **0.7018** |
| 联邦+轻噪声差分隐私（σ=0.01） | 0.6922 |
| 集中训练上界（数据大池化，现实不可行） | 0.7012 |

- 数据阳性率 21.8%~25.1%，贴近真实心衰 30 天再入院流行病学；AUC 0.70 符合临床文献区间（0.65-0.75）
- DP"隐私-效用"分档：轻噪声档仅损失 0.01 AUC，中/强噪声档供高合规场景选择
- 治理流水线实测：单份病历脱敏+结构化约 10-60 秒（本地推理），治理产物零 PHI 残留
- 演示环境：一台普通笔记本（无 GPU）全本地运行，决赛现场零网络依赖

### 真实公开数据集复验（不依赖合成数据假设）

在 UCI 心脏病真实队列（Cleveland，297 例真实患者、冠脉病变终点）上按年龄三分位构造非 IID 三机构场景复验：**联邦模型 AUC 0.9091，追平集中训练上界 0.9019**，高于公开文献同数据集典型基线（0.85-0.90）。合成数据验证机制 + 真实公开数据复验双重佐证，详见《真实数据集复验报告》（docs/真实数据集复验报告.md）。

## 六、商业模式

**收入模型**：
1. **平台佣金**：数据产品交易额的 20%（当前分成架构已内置）
2. **模型 API 订阅**：联邦模型按年授权（定价 ¥80,000/年起，目录已上架）
3. **治理服务费**：为医院提供病历治理与数据资产化服务（按数据集计价）
4. **监管 SaaS**：面向卫健/数据局的合规看板年费

**目标客户**：区域医共体（三甲+县医院+社区中心）、卫健/数据主管部门、保险精算与药研 CRO（数据买方）

**竞争差异化**：不做"又一个医疗大模型"，而是做大模型时代的数据要素基础设施——与医疗 AI 应用是共生关系（我们的应用生态就是数据买方），与隐私计算厂商相比多了"流通交易+监管合规"的完整闭环。
