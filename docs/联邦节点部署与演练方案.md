# 联邦节点部署与双机隔离演练方案（P1.1 医院侧节点 + P1.2 mTLS/密钥轮换）

> 验收口径（生产化改造计划 P1.1）：在两台互不相通的内网机器部署节点 Agent，
> 完成一次完整联邦训练，**原始数据零传输（流量抓包验证）**。

## 1. 架构与信任边界

```
┌─ 医院内网 A（互不相通）─┐   ┌─ 医院内网 B ─┐   ┌─ 平台侧（coordinator）─┐
│ node_agent 容器         │   │ node_agent   │   │ 瓯医数链后端            │
│  · 仅持有本院 CSV 凭证  │   │  · 同左      │   │  · 节点注册/任务管理     │
│  · 本地训练（内存中）   │   │              │   │  · 参数聚合（FedAvg）    │
│  · 参数 AES-GCM 加密上行│   │              │   │  · 只见密文与聚合量      │
└──────────┬──────────────┘   └──────┬───────┘   └───────────▲────────────┘
           └──────────── HTTPS(参数信封) ────────────────┘
```

- **节点侧**（`backend/node_agent/`，Docker 单容器）：不依赖平台代码包，
  仅 numpy + cryptography；原始数据只出现在本院机器内存中。
- **平台侧**：`app/routers/federation_nodes.py`（协议端点）+
  `app/services/federation_coordinator.py`（聚合）；表
  `federated_nodes` / `distributed_federation_jobs` / `distributed_job_updates`
  （台账已登记，参数列 `payload_enc` 应用层 AES-256-GCM 加密信封）。

## 2. 部署步骤

### 2.1 平台侧（coordinator）

```bash
# .env 增配（与节点共享的参数信封密钥，32 字节 base64：
#   openssl rand -base64 32）
FEDERATION_PARAM_KEY=<32字节base64密钥>
# 多版本密钥环（P1.2 轮换用，格式 "key_id:key" 逗号分隔，最后一个为活跃写入密钥；
# key_id = sha256(key)[:8] hex，由 scripts/rotate_federation_key.py 自动生成。
# 留空 = 回退上面的单密钥。配置了密钥环后应 unset FEDERATION_PARAM_KEY）
# FEDERATION_PARAM_KEYS=<key_id1>:<key1>,<key_id2>:<key2>
DEMO_MODE=false            # 生产形态
```

### 2.2 注册节点（平台管理端/超管）

```bash
curl -X POST https://<平台域名>/api/federation/nodes \
  -H "X-Admin-Token: <超管token>" -H "Content-Type: application/json" \
  -d '{"name": "温附一院"}'
# → {"node_id": "...", "node_token": "<仅此一次返回>", ...}
```

### 2.3 医院侧节点（两台内网机器分别执行）

```bash
cd backend/node_agent
docker build -t oumed-node-agent .

# 本院数据：13 特征 + readmit_30d 列的 CSV（只读挂载，路径仅注入本容器）
docker run --rm -i \
  -e COORDINATOR_URL=https://<平台域名> \
  -e NODE_ID=<上一步 node_id> \
  -e NODE_TOKEN=<上一步 node_token> \
  -e FEDERATION_PARAM_KEY=<与平台一致的密钥> \
  -e NODE_DP_SEED=7 \
  -e TLS_CA_CERT=/certs/ca.crt \
  -e TLS_CLIENT_CERT=/certs/client-node1.crt \
  -e TLS_CLIENT_KEY=/certs/client-node1.key \
  -v /data/hospital_ehr.csv:/data/ehr.csv:ro \
  -v /certs:/certs:ro \
  -e DATA_PATH=/data/ehr.csv \
  oumed-node-agent
```

TLS 变量说明（P1.2）：`TLS_CA_CERT`=联邦 CA（验证平台服务端）；
`TLS_CLIENT_CERT/TLS_CLIENT_KEY`=联邦 CA 签发的节点客户端证书（mTLS 双向认证）。
三者全部留空 = 系统 CA 的单向 TLS（联调可用）。

无 Docker 环境：`pip install -r requirements.txt` 后
`python -m node_agent.main`（同一组环境变量）。

### 2.4 创建联邦任务（平台侧）

```bash
curl -X POST https://<平台域名>/api/federation/nodes/jobs \
  -H "X-Admin-Token: <超管token>" -H "Content-Type: application/json" \
  -d '{"node_ids": ["<节点A>", "<节点B>"], "rounds": 12, "local_epochs": 3, "dp_sigma": 0.01}'
```

节点 Agent 自动发现任务（`/my-jobs`）并开始：collecting（上传联邦统计）
→ 逐轮本地训练 + 加密上行 → done（输出加权 AUC 与存证哈希）。

## 3. 流量抓包验证（原始数据零传输）

### 3.1 抓包位置与命令

```bash
# 平台侧抓 ingress 流量（或节点侧抓 egress，结论一致）
sudo tcpdump -i any -w drill.pcap host <节点IP> and port 443
# 明文联调环境（HTTP）时：port 8100，可直接字符串检索
```

### 3.2 判定标准

| 检查项 | 方法 | 通过标准 |
|---|---|---|
| 传输内容 | Wireshark 打开 drill.pcap | TLS 1.3 会话，应用数据全部为密文 |
| 无行级数据 | `strings drill.pcap \| grep -iE "readmit|hba1c|ejection_fraction"` | 零命中（特征/标签名不出现在流量中） |
| 上行体量 | 抓包统计上行字节数 | 每节点每轮仅 1 次 POST，体量 ~KB 级（信封 <2KB），与样本行数无关 |
| 数据库侧 | 查 `distributed_job_updates.payload_enc` | 全部为 `enc2:<key_id>:…` 密文；解密后仅 `coef/n/local_auc` 三个聚合字段 |

> HTTPS 下流量本已加密，"零传输"的强验证来自两层：① 应用层信封独立加密
> （即使 TLS 终止后平台日志/DB 中也无明文行数据）；② 抓包上行体量与
> 样本量无关（10 行与 100 万行的上行字节数同为 KB 级）。

## 4. 协议参考（排障用）

| 端点 | 认证 | 说明 |
|---|---|---|
| `POST /api/federation/nodes` | X-Admin-Token | 注册节点（token 一次性返回） |
| `POST /api/federation/nodes/jobs` | X-Admin-Token / RBAC | 创建任务（≥2 节点） |
| `GET /api/federation/nodes/my-jobs` | X-Node-Id + X-Node-Token | 节点发现被指派任务 |
| `GET /api/federation/nodes/jobs/{id}/assignment` | 节点凭证 | 拉取当前轮全局模型+标准化器 |
| `POST /api/federation/nodes/jobs/{id}/moments` | 节点凭证 | 上传联邦统计 (n,sum,sum_sq) |
| `POST /api/federation/nodes/jobs/{id}/rounds/{r}/update` | 节点凭证 | 上传本轮参数（{coef,n,local_auc}） |
| `GET /api/federation/nodes/jobs/{id}` | 管理面 | 任务状态/结果/存证哈希 |

- 凭证错误 → 401；非任务成员 → 403；重复提交 → 409（断点重连幂等跳过）；
- 轮次错位 → 409（携带当前轮次提示）。
- 断点重连：Agent 重启后按 assignment 幂等续跑（已提交轮次自动跳过）。

## 5. P1.2 增强：mTLS 双向认证与密钥轮换

### 5.1 mTLS 部署（传输层防中间人）

在 TLS 1.3 单向加密之上，平台对节点面端点强制校验医院节点客户端证书：

```bash
# 平台侧一键签发（openssl，零新依赖）：CA + 服务端证书 + N 个节点客户端证书
cd deploy/tls && bash gen-certs.sh <平台域名> <节点数> ./certs

# 部署 nginx-mtls.conf（与 nginx-tls.conf 二选一，避免 443 重复监听）：
#   ca.crt → /etc/nginx/ssl/ca.crt；server.crt/key → fullchain.pem/privkey.pem
nginx -t && nginx -s reload
```

保护范围：仅节点面 4 个端点（my-jobs / assignment / moments / rounds update）
要求客户端证书，管理面/患者端浏览器访问不受影响（`ssl_verify_client optional`
+ location 内 `if ($ssl_client_verify != SUCCESS) { return 403; }`）。

### 5.2 中间人攻击模拟验证（P1.2 验收）

| 场景 | 模拟方式 | 预期结果 |
|---|---|---|
| ① 无客户端证书 | `curl --cacert certs/ca.crt https://<域名>/api/federation/nodes/my-jobs` | TLS 握手失败（400/certificate required），请求不到应用层 |
| ② 非联邦 CA 证书 | 用自签"野"证书作客户端证书重放 | 握手被拒（unknown ca） |
| ③ 联邦 CA 正式证书 | 节点 Agent 带 client-node1.crt 访问 | 握手成功 → 401（应用层凭证校验接管） |

> ③ 的语义：mTLS（传输层）与节点 token（应用层）是两层独立防线，握手成功
> 不代表放行——两层各自被攻破才可能接入。单测等价验证：
> `tests/test_federation_p12_security.py` 用 socketpair 真实 TLS 握手覆盖 ①②③。

### 5.3 密钥轮换（信封 enc2 + 多版本密钥环）

信封线格式 `enc2:<key_id>:<nonce>:<ct>` 自带密钥版本号（key_id = sha256(key)[:8]），
平台按 key_id 在密钥环寻钥；旧 enc1 信封保留解密兼容（过渡期）。

```bash
cd backend && python scripts/rotate_federation_key.py --out rotation.md
# 输出三步操作：
# ① 平台配置 FEDERATION_PARAM_KEYS="旧id:旧key,新id:新key"（过渡期，旧解新写）→ 重启；
# ② 各节点 FEDERATION_PARAM_KEY 更新为新 key → 重启 Agent（任一节点完成一轮上传即验证通过）；
# ③ 确认无在途任务后，密钥环收敛为 "新id:新key" → 旧密钥销毁。
```

**密钥泄露场景语义（P1.2 验收）**：轮换完成后旧密钥移出密钥环并销毁 →
其 key_id 不在环中，历史密文（`distributed_job_updates.payload_enc` 归档）
永久不可解密——即使泄露的旧密钥被攻击者持有也无效。
单测：`test_rotation_history_undecryptable`。

操作纪律：新密钥走密钥管理通道分发（不出现在聊天/邮件/仓库）；过渡期 ≤1 个
任务周期；在变更台账登记时间/原因/执行人/新 key_id。

## 6. P1.3 增强：拔节点演练 / 断点续训 / 恶意参数检测

### 6.1 拔节点 30 分钟演练（断点续训验收）

1. 按第 2 章部署两节点并建任务（建议 `rounds≥6`，留足中断窗口）；
2. 训练进行中（如第 3 轮）直接对节点 B 断电/拔网线——**无需任何平台操作**：
   未提交节点缺位时任务停在当前轮等待（协议天然容错）；
3. 若为计划性检修（窗口期），管理面先暂停任务，避免等待期间其他节点空轮询：
   ```bash
   curl -X POST $BASE/api/federation/nodes/jobs/$JOB_ID/pause \
        -H "X-Admin-Token: $ADMIN_TOKEN"
   # → {"status": "paused", ...}；期间节点 Agent 轮询 assignment 自然等待（零改动）
   ```
4. 观察掉线可见性：节点列表 `last_seen_at` 停更；任务详情 `progress` 可见
   哪个节点 `last_update_round` 落后（拔线节点直接定位）；
5. 30 分钟后节点 B 复电重连（Agent 容器 `docker restart` 即可），管理面恢复：
   ```bash
   curl -X POST $BASE/api/federation/nodes/jobs/$JOB_ID/resume \
        -H "X-Admin-Token: $ADMIN_TOKEN"
   # → 按中断时轮次回到 running（collecting 阶段中断则回 collecting）
   ```
6. 节点 B 补齐当前轮提交 → 任务继续推进至 done；
7. **验收判定**：任务完成后 `final_auc` 与"全程无中断的对照任务"（同配置同数据）
   一致——聚合只依赖已提交参数，暂停/掉线不改变任何已收参数，结果确定性一致
   （自动化背书：`tests/test_federation_p13_resilience.py::test_pause_resume_final_auc_matches_uninterrupted`）；
   任务 `prev_hash/event_hash` 正常入链。

### 6.2 恶意参数检测

平台对每份上行参数计算与当前全局模型的 cosine 相似度，低于
`FEDERATION_COS_THRESHOLD`（默认 0.0，负数关闭）即 422 拒绝：
恶意参数**不落库、不参与聚合、不留存证**，响应 detail 携带实测 cosine 值
（平台侧同步 warning 日志）。合法 DP 更新方向与全局模型高度一致（≈1），
翻转/投毒（≈-1）、正交垃圾（≈0）均被拦截。首轮全局模型为零向量时方向无意义，
自动跳过检测。

演练注入（对节点 A 换一个伪造 trainer 输出即可，或直接 curl 明文联调模式）：
将 `coef` 取反后上行 → 预期 422；随后恢复合法程序 → 任务不受影响照常完成。
